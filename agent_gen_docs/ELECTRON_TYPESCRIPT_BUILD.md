# Electron + TypeScript Build Architecture

## Overview

This project uses **Vite** to bundle TypeScript source code into JavaScript that Electron can run. Electron is a desktop framework that renders web technologies (HTML, CSS, JavaScript) as a native application. Since Electron only understands JavaScript—not TypeScript—we use Vite as a build tool to transform TypeScript into JavaScript.

## Architecture

```
TypeScript Source Files (src/*.ts)
            ↓
        Vite Build
            ↓
Bundled JavaScript (dist/assets/index-*.js)
            ↓
dist/index.html (references bundled JS)
            ↓
Electron Main Process (electron/main.js)
            ↓
Loads dist/index.html
            ↓
Browser Renderer Process (runs bundled JS)
```

## Directory Structure

```
frontend/
├── src/                          # TypeScript source files
│   ├── index.html               # Entry point (Vite processes this)
│   ├── renderer.ts              # Renderer process entry point
│   ├── shell.ts                 # UI shell component
│   ├── audio-source-selector.ts # Audio device selector component
│   ├── audio-source-client.ts   # HTTP client for backend API
│   └── styles.css               # Styles
├── electron/                     # Electron main process
│   ├── main.js                  # Creates window, loads HTML
│   └── preload.js               # Security bridge (IPC channels)
├── dist/                         # Generated by Vite (DO NOT EDIT)
│   ├── index.html               # Built HTML
│   └── assets/                  # Bundled JS and CSS
├── vite.config.mjs              # Vite configuration
├── tsconfig.json                # TypeScript configuration
└── package.json                 # Project metadata and scripts
```

## Build Pipeline Explained

### 1. Source Code (TypeScript)

TypeScript files import each other using `.ts` extensions (ESM style):

```typescript
// src/renderer.ts
import { Shell } from "./shell.ts";
import { AudioSourceSelector } from "./audio-source-selector.ts";
import { HttpAudioSourceClient } from "./audio-source-client.ts";
```

### 2. Vite Bundling

When you run `npm run build`, Vite:
- Reads `src/index.html` as the entry point
- Parses the `<script src="./renderer.ts">` tag
- Recursively resolves all imports (shell.ts → audio-source-selector.ts → audio-source-client.ts)
- Transpiles TypeScript to JavaScript
- Bundles everything into a single JS file
- Generates a hash-based filename (e.g., `index-8LMQoonz.js`) for cache-busting
- Outputs to `dist/`

### 3. Output Structure

Vite generates:

```
dist/
├── index.html                          # Updated HTML
│   <script src="./assets/index-8LMQoonz.js"></script>
├── assets/
│   ├── index-8LMQoonz.js              # All bundled JS
│   └── index-C--2euhM.css             # All bundled CSS
```

The paths use `./` (relative), so Electron can load them via `file://` on all platforms (Windows, Mac, Linux).

### 4. Electron Loading

`electron/main.js` loads the built HTML:

```javascript
const { app, BrowserWindow } = require("electron");
const path = require("path");

function createWindow() {
  const win = new BrowserWindow({...});
  win.loadFile(path.join(__dirname, "../dist/index.html"));  // ← Loads built HTML
  app.whenReady().then(() => createWindow());
}
```

The browser renderer process runs the bundled JS, which:
- Creates the Shell UI
- Initializes the AudioSourceSelector
- Fetches audio sources from the backend

## Development Workflow

### Running Locally

1. **Start the backend** (FastAPI):
   ```bash
   cd backend
   python -m uvicorn app.main:app --reload
   ```
   This runs on `http://127.0.0.1:8000` and provides:
   - `PUT /api/audio/sources` — register OS audio devices
   - `PUT /api/audio/sources/active` — set active device

2. **Build and run the frontend**:
   ```bash
   cd frontend
   npm run start
   ```
   This runs `npm run build` then `electron .`, which:
   - Compiles TypeScript via Vite
   - Launches the Electron app with the compiled output

### Development Commands

| Command | Purpose |
|---------|---------|
| `npm run build` | Build TypeScript to `dist/` using Vite |
| `npm run start` | Build then launch Electron |
| `npm run typecheck` | Check TypeScript types without building |
| `npm test` | Run vitest unit tests |
| `npm run test:watch` | Run tests in watch mode |

## Windows Considerations

### Path Handling

Electron uses `path.join(__dirname, ...)` which is platform-aware:
- **Windows**: `C:\Users\...\dist\index.html`
- **macOS/Linux**: `/home/.../dist/index.html`

Vite's relative paths (`./assets/...`) work on all platforms when loaded via `file://`.

### HTTP Client

`AudioSourceClient` makes HTTP requests to `http://127.0.0.1:8000`. This works on Windows without extra configuration.

### Building for Production

To package for Windows (.exe):
```bash
npm install -g electron-builder
npm run build
electron-builder --win
```

This creates a Windows installer in `dist/`.

## Troubleshooting

### "Audio selector not showing / error in red"

**Cause**: Backend is not running or not accessible.

**Fix**: Ensure the FastAPI backend is running on port 8000:
```bash
cd backend
python -m uvicorn app.main:app --reload
# Should print: "Uvicorn running on http://127.0.0.1:8000"
```

### "Module not found: ./shell.ts"

**Cause**: TypeScript import extension was wrong or Vite config is broken.

**Fix**: 
- Verify all imports in `src/*.ts` use `.ts` extension (not `.js`)
- Verify `vite.config.mjs` exists and has `root: "src"`, `outDir: "../dist"`
- Delete `dist/` and rebuild: `npm run build`

### "Electron app is blank / shows 404"

**Cause**: `dist/index.html` doesn't exist or paths are wrong.

**Fix**:
- Run `npm run build` to generate `dist/`
- Check that `electron/main.js` loads `path.join(__dirname, "../dist/index.html")`
- Check browser console (`Ctrl+Shift+I`) for errors

### App works locally but not after packaging

**Cause**: Relative paths break when packaged.

**Fix**: Ensure `vite.config.mjs` has `base: "./"` so assets use relative paths.

## Key Files Reference

### vite.config.mjs
Configures Vite to:
- Use `src/` as the root directory
- Output to `dist/`
- Use relative paths (`base: "./"`) for Electron compatibility

### tsconfig.json
- Target: `ES2020` (JavaScript version supported by Electron)
- Module: `ESNext` (modern imports/exports)
- Output: `dist/` directory
- Source: `src/` directory

### electron/main.js
- Creates a BrowserWindow (1200x800)
- Loads `dist/index.html` (the built HTML)
- Sets up preload script for IPC security

### src/renderer.ts
- Entry point for the renderer process
- Creates the UI shell
- Initializes components and fetches data from backend
- Catches and displays errors if backend is unavailable

## Why This Architecture?

1. **TypeScript Safety** — Static type checking catches errors before runtime
2. **Component Modularization** — Separate files for Shell, AudioSourceSelector, Client
3. **Bundling** — Single JS file improves load performance and simplifies distribution
4. **Cross-Platform** — Relative paths work on Windows, Mac, and Linux
5. **Development** — Hot reload and type checking during development
